## AI 速读卡

- **产品一句话：** 用强状态机问答把 PCB 产品工艺、功能区域和冷量输入变成可追溯静态计算、三年历史仿真与七天预测。
- **核心循环：** 选唯一产品模板 → 问答采集 → 强校验 → 静态计算 → 历史仿真/未来预测 → 图表下钻 → CSV。
- **目标平台：** 仅桌面端 Web；工程师与管理员两角色；MySQL 持久化。
- **硬约束：** 一项目一产品、一地区域、一地区工序、主要工序全覆盖、计算字段结构化落库、结果与输入快照绑定。
- **推荐默认：** React + TypeScript + Vite、FastAPI、MySQL、Redis、Celery、ECharts、Docker Compose。
- **发挥空间：** 微交互、图表排版、空状态、动效和内部代码组织可优化，但不得改变状态机与计算口径。
- **P0 验收：** HDI 示例从管理员发布模板到工程师导出区域/工艺逐时 CSV 全链路跑通。
- **最容易翻车：** 把自然语言直接写入计算字段、模板更新污染既有项目、工艺与空间聚合口径混淆、旧任务覆盖新结果。
- **超预期机会：** 影响分析卡、结果血缘抽屉、跨 Tab 筛选链接、四主题组合的无跳变双语体验。

## 第一章：产品概述

PCB-CDSO v0.6 是一款工艺驱动的 PCB 工厂冷源专家系统，让暖通/厂务工程师通过受控问答完成静态冷量计算、历史仿真和未来预测，而无需在分散 Excel、自由表单与不可追溯经验公式之间反复核对。

### 1.1 差异化对比表

以下对比基于项目内 v0.5.1 与现有原型，不构成对外部商业产品现状的声明。

| 功能 | v0.5.1 / 传统方式 | v0.6 | 实现方式 |
|---|---|---|---|
| 建模起点 | 用户自由建立功能区域 | 产品模板决定固定主工序与候选辅助工序 | 一项目绑定一个版本化产品模板快照 |
| 输入方式 | 左树右表单、Excel 导入、可跳过 | 仅问答入口，计算字段受控提交 | 配置化文案 + 代码守门状态机 |
| 输入可信度 | 默认值与自由值混杂 | 值、单位、来源、规则版本完整记录 | 字段级血缘与分级校验 |
| 工艺关系 | 工艺只是区域名称/模板参考 | 区域必须绑定工序，主要工序必须全覆盖 | 工序覆盖门禁与工艺聚合 |
| 空间可视化 | 地图、2D Canvas、热力图 | 删除地图和 2D 区域画布 | 冷量改用图表与区域详情表达 |
| 动态结果 | 气象法与比例系数法并存，口径复杂 | 统一经验模型：静态基准 × 天气系数 × 生产系数 | 版本化二维系数表与逐时任务 |
| 数据库 | PostgreSQL + TimescaleDB | MySQL | 分区/索引、当前批次明细、归档批次汇总 |
| 角色 | 4 角色、多项目成员 | 管理员、工程师两角色 | 项目单一归属与后端授权 |
| 输出 | PDF、Excel、CSV、P&ID | 详细图表 + 逐时 CSV | 结果中心与异步导出 |

### 1.2 三类用户画像

#### 用户 A：暖通/厂务工程师（核心用户）

- **核心目标：** 快速建立工厂区域数据，算清静态冷量并理解逐时变化。
- **最大不满：** Excel 公式、工艺要求和区域数据分散，修改后难判断哪些结果已失效。
- **切换触发点：** 系统能指出缺什么、为什么缺、参数来自哪里，并下钻到单个区域查看计算过程。

#### 用户 B：系统管理员

- **核心目标：** 维护账号、产品工艺模板、标准规则、问答选项和经验系数。
- **最大不满：** 每次修改采集问题或工艺参数都需要开发改代码，且改动会污染历史项目。
- **切换触发点：** 可发布版本化配置，既有项目继续使用自己的快照。

#### 用户 C：暖通/PCB 工艺专家（交付后验证者）

- **核心目标：** 用黄金样例核验公式与参数，不参与日常系统操作。
- **最大不满：** 计算结果缺少输入、公式、中间值和规则版本，难以复核。
- **切换触发点：** 区域结果提供完整血缘，能定位到公式和来源。

### 1.3 可行性边界

| 在范围内（及原因） | 明确排除在外（及原因） |
|---|---|
| 三个内置产品模板：普通多层板、HDI、IC 载板；足以验证模板复杂度差异 | FPC、刚挠、高频、厚铜、金属、陶瓷等内置验收模板；专家核验工作量超出 15 人日 |
| 真实静态公式与可追溯中间值；这是冷量需求计算的可信基线 | 静态计算 Mock；会破坏产品核心价值 |
| 三年历史仿真与七天预测；用于验证逐时数据链 | 动态精度承诺；本版只采用经验系数模型 |
| 水蓄冷信息采集与保存；为后续冷站版本准备输入 | 水蓄冷计算、经济性和控制；本版无冷站模块 |
| 图表精确到功能区域，支持工艺与空间并列聚合 | 地图、2D Canvas、CAD/PDF 底图、区域平面热力图 |
| 按区域/工艺/楼层/建筑/工厂导出逐时 CSV | Excel、PDF、JSON、P&ID 输出 |
| 中英文、明暗主题、桌面网页 | 手机端、原生 App、完整平板编辑 |
| MySQL、Redis、Celery、Docker Compose 单机部署 | K8s、多租户、多人实时协作、企业 SSO |
| 管理员结构化维护文案与预存选项 | 任意拖拽式低代码流程设计器 |

### 1.4 约束分层

| 硬约束 | 推荐默认 | 发挥空间 |
|---|---|---|
| 一个项目等于一座工厂且只生产一种 PCB 产品 | 默认主题跟随操作系统 | 图表组合、留白、微动效可优化 |
| 产品类型在建立空间数据后锁定 | HDI 作为完整主验收示例 | 内部组件拆分可按团队习惯调整 |
| 每个区域只绑定一道工序；每道主要工序至少有一个区域 | 区域面积超出楼层 0%–3% 为可解释警告 | 空状态与引导文案可提高品味 |
| 计算字段必须结构化确认后落库 | 动态系数使用双线性插值 | SSE 或轮询可按实现成本选择 |
| 已发布模板不可原地修改 | 当前仿真批次保留区域逐时明细，归档只留汇总 | 表格虚拟化与图表降采样实现可替换 |
| 输入变化必须使相关结果失效 | 逐时 CSV 单任务最多 1,000,000 行，超出要求缩小筛选 | 可增加不改变 P0 的键盘效率功能 |
| 未经专家核验的参数不得冒充国家标准硬约束 | 工程经验参数产生警告，不产生法规阻断 | 结果中心图表排序与默认视图可调 |
| 前馈控制、冷站配置、设备选型不进入 0.6 | SI 单位作为唯一计算单位 | 后续模块扩展点可预留但不显示灰色入口 |

### 1.5 版本目标

| 编号 | 目标 | v0.6 衡量方式 |
|---|---|---|
| G1 | 工艺驱动闭环 | 三个产品模板可发布；主要工序遗漏时静态计算被阻断 |
| G2 | 受控数据采集 | 计算字段无自然语言直写路径；8 阶段可恢复、可回退、可复核 |
| G3 | 静态计算可追溯 | 每个区域结果可展开输入、来源、公式、中间值和计算版本 |
| G4 | 动态数据可用 | 三年历史与七天预测均支持区域、工艺、楼层、建筑、工厂查询 |
| G5 | 快速理解 | 用户从结果首页 3 次交互内可定位任一功能区域的静态与逐时数据 |
| G6 | 可交付 | 空数据库 Docker Compose 启动后，HDI 示例主链可重复跑通 |

### 3.1 账号、认证与项目列表

#### a) ASCII 界面

```text
+--------------------------------------------------------------+
| 项目                                         〈新建项目〉     |
| 搜索项目...  产品：〈全部〉 状态：〈全部〉 阻断：〈全部〉    |
+--------------------------------------------------------------+
| 深圳 HDI 工厂   HDI v1.0   仿真完成   阻断 0   10 分钟前     |
| 苏州载板试验厂  IC载板 v0.9 数据采集中 阻断 12  昨天          |
| 东莞多层板厂    多层板 v1.0 已归档     只读     2026-07-18    |
+--------------------------------------------------------------+
```

#### b) 交互流程

```text
管理员创建工程师 --> 工程师登录 --> 项目列表 --> 新建项目
                                           |
                                           +-- 无已发布模板 --> 阻断创建，联系管理员
                                           +-- 账号被停用 --> 令牌撤销，回到登录页
                                           +-- 项目已归档 --> 只读查看或恢复
```

空数据库首次启动时，后端必须读取一次性环境变量创建首个管理员；成功写入后不再读取明文密码，并要求部署方删除该变量。0.6 首次登录不强制修改密码，但管理员可在后台重置工程师密码。认证采用成熟密码哈希库和服务端可撤销会话，不自造密码学实现。

#### c) 状态清单

模板生命周期与专家核验是两个正交状态，不得合并：生命周期为 `DRAFT / PUBLISHED / ARCHIVED`，核验为 `UNVERIFIED / VERIFIED`。因此“已发布·待核验”是 0.6 的合法组合；未核验经验参数只能产生警告，不能冒充国家标准硬阻断。

| 状态 | 触发条件 | 视觉标识 | 退出条件 |
|---|---|---|---|
| 正常 | 账号启用、会话有效 | 绿色在线点 | 退出或令牌过期 |
| 会话过期 | 刷新令牌失效 | 顶部提示并跳转登录 | 重新登录 |
| 账号停用 | 管理员停用 | 红色阻断页 | 管理员恢复 |
| 项目归档 | 工程师归档 | 灰色“只读”标签 | 恢复项目 |
| 项目软删除 | 管理员删除 | 仅管理员回收站可见 | 30 天内恢复 |

#### d) 依赖关系

- 读取：用户、角色、项目归属、模板发布状态。
- 写入：登录审计、项目基本信息、归档/恢复记录。
- 不允许：工程师访问他人项目；首次登录不强制改密。
- 复制项目只复制模板快照、结构和已确认输入，生成新项目与新 revision；不复制气象任务、计算批次、预测、导出文件或审计事件。
- 管理员转交项目在同一事务中更换 owner 并递增权限版本；旧所有者后续请求立即返回无权访问。归档项目只读，可查看和导出归档前仍有效的结果，不得发起抓取、计算或预测任务。

#### e) 待决问题

- 无。邮件邀请、SSO 和组织架构已明确排除。

#### b) 交互流程

```text
新建草稿 --> 编辑双语/工序/规则/参数 --> 发布预检 --> 发布

                                         +-- 缺英文 --> 阻断，定位字段
                                         +-- 规则引用不存在 --> 阻断，定位规则

```

#### c) 状态清单

| 状态 | 触发条件 | 视觉标识 | 退出条件 |
|---|---|---|---|
| 草稿 | 新建或复制生命周期版本 | 蓝灰标签，可编辑 | 发布预检通过 |
| 已发布·待核验 | 结构完整、专家尚未签认 | 绿色发布标签 + 琥珀核验标签，只读 | 专家签认产生新核验记录，不改历史快照 |
| 已发布·已核验 | 发布门禁通过且专家签认 | 绿色双标签，只读 | 复制新版本或归档 |
| 已归档 | 管理员归档生命周期版本 | 灰色标签 | 不再供新项目选择；既有项目继续使用 |
| 发布失败 | 检查不通过 | 红色问题清单 | 修复全部阻断项 |

#### d) 依赖关系

- 读取：工序库、标准规则、对话字段定义、系数矩阵。
- 写入：版本化模板与不可变发布快照。
- 模板发布必须原子冻结工序、规则、对话配置、天气系数和生产系数的版本引用；任一引用仍是草稿则阻断发布。
- 新对话配置发布后不会自动切换模板。管理员必须复制模板、选择新对话版本并重新发布；项目创建时复制整套模板快照，后续发布不自动修改既有项目。
- 三个内置模板均以“已发布·待核验”种子快照交付，均可选建项目和复制为草稿；仅 HDI 配套完整验收项目，另外两个只提供只读演示项目，二者不是“只读模板”。

#### e) 待决问题

- 专家核验后的国家标准条款映射尚未提供；0.6 内置参数按“工程经验基线”处理。

#### f) 规则与系数最小契约

- 标准规则包含稳定编码、双语名称、适用产品/工序/字段、运算符、阈值、单位、来源类型、标准编号/版本/条款、核验状态和版本；只有专家签认记录存在时才能标记 `VERIFIED`。
- 天气系数版本包含水温档、温度轴、相对湿度轴、完整矩阵、插值方式和边界策略；生产系数版本包含 `productionRate` 分段点与对应系数。发布后不可原地修改。

#### b) 计算与失败流程

```text

                     |
                     +-- 任一阻断项 --> 不创建任务，返回问题列表
                     +-- 焓值计算异常 --> 整批失败，不生成部分正式结果
                     +-- 输入版本变化 --> 运行中任务可结束但不得设为当前批次
```

核心公式：

```text
Q_civil = area × civil_index / 1000
Q_lighting = lighting_power × lighting_use_factor
  或 area × lighting_density × lighting_use_factor / 1000
Q_people = people_count × people_sensible_index × people_use_factor / 1000
Q_equipment = Σ(count × unit_power × use_factor × indoor_heat_factor)
Q_terminal = Q_civil + Q_lighting + Q_people + Q_equipment

V_fresh = MAX(
  exhaust_makeup + pressure_makeup,
  people_count × min_fresh_air_per_person,
  area × min_fresh_air_per_area
)

Q_fresh_raw = air_density × V_fresh × (h_outdoor - h_indoor) / 3600
Q_fresh = MAX(0, Q_fresh_raw)
Q_HVAC = Q_terminal + Q_fresh
Q_PCW = user_input_pcw × pcw_use_factor
Q_total_reference = Q_HVAC + Q_PCW
```

水温档分流规则固定如下：`Q_terminal` 全量进入区域的 `terminalWaterClass`，`Q_fresh` 全量进入 `freshAirWaterClass`，`Q_PCW` 进入 `PCW`；当末端和新风选择同一档时直接相加。`TOTAL_REFERENCE` 永远由低温冷冻水、中温冷冻水和 PCW 三类结果求和生成，不作为可再次聚合的独立负荷，避免重复计数。

单位契约：设备/照明/PCW 功率统一为 kW，面积 m²，风量 m³/h，干空气密度 kg/m³，焓值 kJ/kg 干空气，公式结果为 kW；湿空气库使用项目站点压力、室外干球/相对湿度和室内设定温湿度。`Q_fresh_raw<0` 代表该时刻没有机械制冷新风负荷，0.6 截断为 0，不计算自然冷却收益、加热或再热。

洁净室换气次数仅用于循环送风/净化要求校验，不把全部净化循环风量计入室外新风冷负荷。

0.6 的经验系数口径固定为：低温和中温冷冻水使用对应水温档的天气系数与工序生产系数；PCW 不受室外天气直接修正，因此 `Kweather(PCW)=1`，只乘工序生产系数；`TOTAL_REFERENCE(t)` 始终等于三类逐时结果之和。天气矩阵在网格点间做双线性插值，超出已发布矩阵边界时钳制到最近边界并记录质量警告；矩阵内部缺点仍阻断计算。该约定是可替换的 Mock/经验模型，不代表物理精度承诺。

`Kweather=1`、`Kproduction=1` 表示静态设计基准。0.6 的 `Kproduction` 只由工序计划的 `productionRate` 经已发布分段表映射，统一作用于该工序区域的低温、中温与 PCW 基准；不再采集未进入公式的人员率或照明率。区域行保存原始两类系数；工艺及空间聚合行的原始系数字段置空，并输出 `effective_combined_coefficient = dynamic_load_kw / static_baseline_kw`（静态基准为 0 时置空），避免伪造不存在的统一聚合系数。

生产系数分段点之间采用线性插值，超出端点时钳制到最近端点并记录警告；计划区间左闭右开，例外日覆盖周计划，无任何匹配计划的小时取 `productionRate=0`。UTC 整点是唯一计算轴和气象连接键；项目当地时间只用于解释计划和展示。历史区间由用户选择本地日期，起点包含、结束日次日 00:00 不包含，最长三个连续日历年；未来预测从下一 UTC 整点起连续 168 小时。夏令时回拨产生的两个本地同名小时分别计算，跳过的本地小时不补造。

## 第四章：超越竞品的差异化功能

### 4.1 工艺覆盖门禁，而非工艺标签

1. **传统结构为何缺少：** 项目内 v0.5.1 以空间 Room 为核心，工艺只作为名称或参考模板，无法判断产品工艺是否完整。
2. **本产品实现：** 产品模板定义固定主要工序；区域绑定工序；静态计算前校验每道主要工序至少有一个区域。
3. **交互流程：**

```text
选择 HDI 模板 --> 自动生成主工序清单 --> 建区域并绑定
        --> 覆盖率 17/18 --> 阻断：缺少“填孔电镀”
        --> 新建/绑定区域 --> 覆盖率 18/18 --> 解锁计算
```

4. **风险与应对：** 模板本身错误会造成错误阻断；通过版本化、待核验状态、项目快照和专家后验验证降低风险。

### 4.2 配置驱动对话、代码固定安全边界

1. **结构原因：** 完全写死的问答难维护，完全可编排的低代码流程又会让管理员绕过计算字段和状态门禁。
2. **本产品实现：** 文案、示例、预存选项、默认值、顺序和启停可配置；字段类型、单位、8 阶段、条件必填、计算公式和权限由代码固定。
3. **交互流程：**

```text
管理员编辑中英文问题 --> 预览 --> 发布配置 v4
          --> 新项目使用 v4
          --> 既有项目继续使用 v3 快照
```

4. **风险与应对：** 配置引用失效；发布前检查字段编码、双语、选项唯一性和条件表达式。

### 4.3 结果血缘与影响分析

1. **结构原因：** Excel 能显示公式，却难记录模板版本和跨表影响；普通看板能显示结果，却通常不解释结果从哪里来。
2. **本产品实现：** 每个结果绑定输入快照、模板/规则/系数/计算版本；修改前显示影响，修改后自动失效相关结果。
3. **交互流程：**

```text
区域详情 --> 查看“设备负荷 241kW” --> 展开来源
         --> 设备清单 + 使用系数 + 散热系数 + 公式
         --> 点击修改 --> 影响：静态/历史/预测将失效
         --> 确认 --> 返回采集并生成修订
```

4. **风险与应对：** 血缘字段过多影响界面；默认折叠，只在区域详情和审计视图展开。

### 4.4 超预期机会（不扩大 P0）

- **影响分析卡：** 用“将失效 1 个静态批次、1 个历史批次、24 个预测摘要”替代泛化警告。
- **结果血缘抽屉：** 单击任何 KPI/图表点可追到区域输入、规则版本和公式。
- **跨 Tab 调试链接：** 筛选同步 URL，开发和专家可直接分享“HDI/LDI/2025 年 7 月”视图。
- **双语无跳变：** 在英文最长文案下预留控件宽度，切换语言不造成 Tab、按钮和图例位移。

### 5.4 数据模型决策

- 工艺和空间分开建模，以支持两条并列聚合路径。
- 模板、对话、规则和系数均做发布快照，避免历史项目被全局更新污染。
- 静态批次保存中间值，动态批次保存系数版本和逐时结果，支持血缘追溯。
- PCW 直接输入，不建设备级 PCW 推导，控制试开发复杂度。
- 水蓄冷只保存，不进入 0.6 计算链。
- 不保存地图、Canvas、CAD/PDF、P&ID、冷站设备和真实控制点位。
- 项目列表中的“数据采集中 / 静态就绪 / 仿真中 / 结果有效 / 结果失效”由阶段、批次和有效性派生，不另建可被写乱的单一项目状态；`ARCHIVED` 是唯一覆盖性生命周期状态。
- 所有关键写请求携带 `expectedInputRevision`。影响分析返回一次性确认令牌；最终确认时再次校验 revision，冲突返回 `409 REVISION_CONFLICT` 且不部分写入。
- 每个异步任务绑定输入、模板、规则、对话、系数和气象批次标识；只有全部标识仍与项目当前 revision 一致时，才能原子切换为 current。

P0 开工前由后端生成并提交 OpenAPI 文件，作为前后端唯一契约；本节资源表不能替代 schema。统一错误体至少包含 `code`、`message_key`、`field_path`、`details`、`request_id`。关键约定：无权限返回 `403 FORBIDDEN`，revision 冲突返回 `409 REVISION_CONFLICT`，业务校验失败返回 `422 VALIDATION_FAILED`；创建计算/导出任务必须接收幂等键，重复请求返回同一任务；列表使用游标或页码分页；任务响应统一返回状态、进度、阶段、已处理量、总量、错误与可重试标志。上传 CSV 的大小、列、编码、时区和 checksum 必须在 OpenAPI 与界面帮助中一致。

OpenAPI 最小操作基线不得少于下表；M0 只允许补充字段，不允许改变方法与主语义：

| Method + Path | 最小请求 | 成功响应 |
|---|---|---|
| `POST /auth/login` | username、password | access token、refresh session、user、locale/theme |
| `POST /projects` | name、templateVersionId、timezone | project、inputRevision=1、整套快照标识 |
| `POST /projects/{id}/answers/impact` | fieldCode、typedValue、expectedInputRevision | impactToken、受影响阶段/批次、警告/阻断 |
| `POST /projects/{id}/answers/confirm` | impactToken、expectedInputRevision、overrideReason | 新 revision、阶段状态、结果失效摘要 |
| `POST /projects/{id}/weather-jobs` | provider 或 CSV batch id、kind、dateRange、idempotencyKey | task |
| `POST /projects/{id}/calculations/static` | expectedInputRevision、idempotencyKey | task |
| `POST /projects/{id}/simulations` | staticBatchId、weatherBatchId、dateRange、idempotencyKey | task |
| `POST /projects/{id}/forecasts` | staticBatchId、weatherBatchId、idempotencyKey | task |
| `GET /projects/{id}/analytics` | batchId、level、entityIds、coolingTypes、timeRange、cursor | series、summary、rows、nextCursor、lineage |
| `POST /projects/{id}/exports/estimate` | 与 analytics 相同筛选 | expandedRowCount、estimatedBytes、allowed |
| `POST /projects/{id}/exports` | 筛选、batchId、idempotencyKey | task、expiresAt |
| `GET /tasks/{taskId}` | 无 | status、stage、processed、total、progressPct、error、retryable |

### 6.4 MySQL 存储策略

- 单项目上限：10 栋、每栋 10 层、全项目 300 个区域。
- 历史逐时区域结果最大约 300 × 26,304 = 7,891,200 条。
- 逐时表按时间或项目/批次策略分区，至少建立 `(project_id, batch_id, timestamp_utc)` 与维度 ID 索引。
- 逐时数据库采用宽表：每个区域每小时一行，列内保存 CHW_LOW、CHW_MEDIUM、PCW 三类负荷；TOTAL_REFERENCE 查询时求和，不重复落库。因此 300 区域三年约 789 万行。
- 当前有效历史批次保留区域逐时明细；最多 10 个归档批次保留工艺、楼层、建筑、工厂聚合与摘要。新的有效批次原子切换后，旧 current 先转 STALE，再完成聚合归档和区域明细清理。
- 未来预测保留最新完整区域结果和最近 24 次摘要。
- 任务写入使用批次 staging 状态；整批成功后原子切换为 current，失败批次不可被查询为正式结果。
- 临时 CSV 下载文件成功后保留 24 小时，失败或批次失效时立即标记不可下载，由每日清理任务删除。

### 6.5 最大架构风险

最大风险是 MySQL 写入近 800 万区域逐时记录导致任务时间和存储量不可控。应对顺序：

1. NumPy 向量化计算；
2. 批量写入而非逐行 ORM；
3. 聚合结果预计算；
4. 仅保留一个完整区域级当前批次；
5. 若 300 区域验收数据仍不可接受，保持 API 契约不变，将逐时明细替换为列式文件存储，但该替换不进入 0.6 默认实现。

### 6.6 可替换技术原则

推荐 React、FastAPI、Celery、ECharts；若实施仓库已有等价成熟技术，可沿用。不可改变的系统不变量是：问答配置与业务字段解耦、状态机代码守门、模板与结果快照不可变、异步任务幂等、当前批次原子切换、工艺与空间并列聚合、CSV 与界面使用同一查询口径。

为避免试开发期重复选型，M0 必须冻结且全程只使用一套组件库、表单校验库、认证库、湿空气库和 CSV 写出方案；任务进度优先轮询，只有现有骨架已具备稳定 SSE 时才沿用 SSE，不并行实现两套通道。

## 第八章：导出与输出系统

### 8.1 支持的输出格式

| 格式 | 使用场景 | 质量选项 | 备注 |
|---|---|---|---|
| Web 图表 | 快速理解全厂、工艺和区域冷量 | 时间粒度、筛选维度、曲线显示项 | P0 主要输出 |
| CSV UTF-8 | 下游分析历史仿真或未来预测 | 区域/工艺/楼层/建筑/工厂粒度 | 含 BOM，兼容常见表格工具 |

不支持 Excel、PDF、JSON、图片报告和 P&ID。

### 8.2 CSV 文件结构

单次导出只生成一个数据 CSV，不另附 manifest；批次、模型、筛选和版本元数据全部作为数据列重复写入，以保持交付格式唯一。

```text
hourly-load-process-ldi-2024_2026.csv
```

逐时 CSV 必含：

| 字段 | 说明 |
|---|---|
| `timestamp_utc` | UTC ISO-8601 |
| `timestamp_local` | 项目当地时间 |
| `timezone` | IANA 时区 |
| `project_id` / `batch_id` | 项目与批次 |
| `aggregation_level` | ZONE / PROCESS / FLOOR / BUILDING / FACTORY |
| `entity_id` / `entity_name` | 对应维度实体 |
| `cooling_type` | CHW_LOW / CHW_MEDIUM / PCW / TOTAL_REFERENCE |
| `static_baseline_kw` | 静态基准 |
| `weather_coefficient` | 天气系数 |
| `production_coefficient` | 生产系数 |
| `effective_combined_coefficient` | 聚合行的综合有效系数；区域行可为空 |
| `dynamic_load_kw` | 逐时结果 |
| `model_label` | `EXPERIENCE_COEFFICIENT` |

CSV 采用长表展开：每个“时间 × 所选实体 × cooling_type”一行。选择“全部冷源”时最多输出 CHW_LOW、CHW_MEDIUM、PCW、TOTAL_REFERENCE 四行；不存在的分项不输出。`TOTAL_REFERENCE` 是三类分项之和的参考行，任何再次汇总必须排除该行，不能与三个分项相加。功能区的 CHW_LOW/CHW_MEDIUM/PCW 行输出原始天气/生产系数；功能区级 `TOTAL_REFERENCE` 及 PROCESS/FLOOR/BUILDING/FACTORY 聚合行的两列原始系数为空，只输出综合有效系数。导出行数以展开后的查询 count 为准，而非数据库宽表物理行数。

### 8.3 导出流程

```text
结果中心当前筛选
        |
        v
估算行数/文件大小
        |
        +-- >1,000,000 行 --> 阻断，要求缩小时间或实体范围
        |
        v
创建导出任务 --> 统一聚合查询 --> 分块写 CSV --> 校验行数/编码 --> 可下载
                           |
                           +-- 查询失败 --> 任务失败，可原筛选重试
                           +-- 批次失效 --> 终止导出，要求重新计算
```

同一用户最多同时运行 2 个 CSV 任务；同一筛选和批次的重复请求复用已有任务。

- 密码使用成熟自适应哈希；数据库不保存明文密码或令牌。
- 访问令牌短期有效，刷新令牌可撤销；账号停用后撤销活动会话。
- 计算、模板发布、关键修改、导出和项目转交写审计日志。
- 仅支持桌面网页；设计基准 1440×900，最低 1280×720。
- 所有计算底层使用 SI 单位；UI 不提供英制计算切换。
- 数据库存储 UTC；界面显示项目当地时间；CSV 同时输出 UTC、本地时间和时区。

## 第十一章：开发者交接说明

### a) 实现顺序建议

你必须按纵向切片实现，不要先分别做完整前端和完整后端。

| 里程碑 | 时间 | 你需要交付的可观察结果 |
|---|---:|---|
| M0 基线 | 0.5 天 | 空库启动、登录壳、设计令牌、双语和主题可切换 |
| M1 身份与模板 | 1 天 | 管理员创建工程师，发布 HDI 模板，工程师可选模板建项目 |
| M2 对话采集 | 2 天 | 8 阶段、受控答案、保存恢复、阻断和影响分析可跑 |
| M3 静态计算 | 1 天 | 区域公式、工艺/空间聚合、血缘详情可查看 |
| M4 仿真预测 | 1 天 | 气象任务、三年经验仿真、七天预测可完成 |
| M5 结果中心 | 1 天 | 五 Tab、统一筛选、区域下钻和主要图表可用 |
| M6 导出收口 | 1 天 | CSV、审计、示例、关键测试和部署脚本通过 |

每个里程碑先固化小规格、API schema、状态转换和验收测试，再写实现。依赖成熟组件；不要自造认证、表格、图表、湿空气函数、任务队列或 CSV 框架。

该排期是用户确认的 15 人日时间盒目标，不是经历史速度校准的承诺，范围负荷显著偏高。两名开发必须按纵向切片并行，至少每天一次合并和门禁；任何里程碑未过门禁时，不得用关闭校验、伪造进度或隐藏失败来“按时完成”。项目负责人应在当日记录缺口并让需求方显式选择延长时间或从尚未实现的外围能力中裁剪，G0–G4 核心计算闭环不得静默降级。

### b) 最可能导致返工的三个决策

#### 决策 1：动态逐时数据如何存储

- **当前决策：** MySQL 保存当前完整区域批次，归档只留聚合。
- **安全默认：** 批量写入、明确索引、staging 批次原子切换。
- **改变信号：** 300 区域任务在目标硬件超过 600 秒，或存储增长超过部署预算；此时保持 API 不变，评估列式文件。

#### 决策 2：问答配置的可编辑边界

- **当前决策：** 管理员只改文案、选项、默认值、顺序、显示和版本；不能改字段类型、单位、主阶段和强校验。
- **安全默认：** 字段 registry 与状态机写在受测试代码中。
- **改变信号：** 连续多个版本都需要新增字段类型或阶段，而不是只改内容；届时单独设计流程 DSL，不要在 0.6 临时拼接。

#### 决策 3：标准规则的权威性

- **当前决策：** 未核验参数是工程经验基线，只警告；已核验规则才可阻断。
- **安全默认：** 内置三个模板均标记“待核验”，结果标记“待专家验证”。
- **改变信号：** 业主提供标准编号、版本、条款和适用范围映射，并由专家签认；届时发布新规则版本，不改旧快照。

### c) 哪里必须严格，哪里可以灵活

| 章节/主题 | 类型 | 说明 |
|---|---|---|
| 领域模型、唯一产品/工序绑定 | 约束 | 改变会破坏 top0 工艺驱动 |
| 状态机与分级校验 | 约束 | 不能让自由输入绕过门禁 |
| 静态公式与新风口径 | 约束 | 界面、CSV、测试必须统一 |
| 动态经验公式与无精度承诺 | 约束 | 不得暗示真实控制能力 |
| 模板/结果快照和任务幂等 | 约束 | 决定可追溯性和并发正确性 |
| UI 视觉与微交互 | 建议 | 可提高品味，但保持 UI 归档设计语言 |
| React 组件拆分、CSS 方案 | 建议 | 团队可按成熟实践调整 |
| SSE 或轮询 | 建议 | 只要任务可恢复、进度 ≤2 秒更新即可 |
| MySQL 表物理拆分 | 建议 | 可正规化优化，但 JSONC 语义和查询契约不变 |

### d) 已知的未知项

1. 正式历史气象与预报 Provider、凭据、限额和许可尚未确定；必须保留 Provider 接口与 CSV 兜底。
2. 国家标准条款到工序参数的权威映射尚未提供；0.6 不得自行宣称经验参数为法规硬约束。
3. 暖通专家的 10 个黄金静态样例将在功能交付后提供；交付前只完成开发公式自测。
4. 天气和生产经验系数尚未校准；历史仿真和未来预测不设精度验收。
5. 目标部署硬件未最终固定；性能结果必须附测试环境。

这些未知项不会阻断试开发闭环，但必须出现在验收记录和后续版本计划中。

### e) 验收剧本

实施仓库必须提供版本化的 `fixtures/acceptance`，包含种子 manifest、固定账号/项目标识、三份静态输入、24 小时动态输入、三年气象 CSV、预期结果和 checksum。以下剧本均按 Given/When/Then 自动执行；每次从空库或明确 seed 开始，HTTP 状态、业务错误码、数值容差和任务超时必须进入断言，测试结束清理临时文件。

#### 验收剧本 1：管理员发布配置

在空数据库启动系统，以管理员登录，创建工程师账号；复制 HDI 模板为草稿，检查双语、主要工序、规则、对话和系数后发布。应看到发布检查全部通过、已发布版本只读，并通过数据库记录和审计日志验证版本不可变。

#### 验收剧本 2：工程师完成受控问答

以工程师登录，创建“深圳 HDI 工厂”，走完 8 阶段。故意遗漏“填孔电镀”区域，应看到主要工序覆盖阻断；补充区域后继续。输入面积使楼层超出 4%，应阻断；改为超出 2%，填写原因后应出现警告但允许继续。刷新浏览器后应从首个未完成问题恢复。

#### 验收剧本 3：静态计算与失效

完成输入后运行静态计算，打开任一区域详情，应看到土建、照明、人员、设备、新风、PCW 的输入、公式、中间值和来源。修改区域设备功率并确认影响，旧静态、历史和预测结果应标记失效，且不能继续作为 CSV 的有效批次。

#### 验收剧本 4：历史仿真、未来预测与五维聚合

使用 HDI 示例气象数据运行三年仿真和七天预测。在结果中心分别按区域、工艺、楼层、建筑和工厂查询；静态、历史、预测 Tab 切换后筛选不丢失。通过 API 响应、图表 tooltip 和统一聚合服务交叉验证同一筛选口径一致。从结果首页开始，以“打开区域筛选 → 选择目标区域 → 打开详情”三次交互同时看到该区域静态分项与逐时曲线，作为 G5 的确定验收口径。

#### 验收剧本 5：CSV、权限与四主题组合

按 LDI 工艺导出逐时 CSV，检查 UTF-8、UTC/本地时间/时区、批次、静态基准、天气系数、生产系数和动态负荷列，行数与数据库 count 一致。再用另一个工程师账号请求该项目 API，必须返回无权访问。最后运行中文/英文 × 明/暗四种 E2E 截图，主路径不得出现阻断级错位或缺失资源键。

#### 验收剧本 6：并发修订与旧任务保护

以同一工程师的两个浏览器 Tab 打开同一项目。Tab 甲提交 revision 12→13 后，Tab 乙携带 `expectedInputRevision=12` 确认修改，必须返回 `409 REVISION_CONFLICT` 且数据库无部分写入。随后人为让旧仿真任务晚于新任务完成，旧任务可保留日志但不得成为 current；重复使用同一幂等键创建任务必须返回同一 task id。容器重启后，排队/运行任务按既定重试策略恢复或明确失败，不得生成半成品有效批次。
